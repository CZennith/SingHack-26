# Analysis result contract

Version **1.0.0** is the common, versioned envelope for future client-analysis calculators. It is
implemented by the strict dataclass-backed validator in `src/contracts/validation.py`; the JSON
Schema in this directory is generated by `generate_json_schema()` and is not maintained separately.

## Snapshot, calculator result, and future LLM packet

The client snapshot is a deterministic consolidation of database facts at an as-of date. It keeps
portfolio-level records, source references, and data-quality flags.

A calculator result is a separate artifact produced from a snapshot. It contains facts, findings,
evidence, warnings, and assumptions in this contract. Findings are observations and must be
evidence-backed; RM review remains required where the result says so.

A future LLM input packet may combine a snapshot and one or more validated calculator results. No
LLM, prompt, interpretation, recommendation, or packet builder is implemented here.

|---|---|---:|---|---|---|
| `result_metadata` | object | yes | Result identity and input-version metadata; strict fields only. | 1.0.0 | yes |
| `facts` | array of Fact | yes | Calculated or retrieved values without interpretation. | 1.0.0 | yes |
| `findings` | array of Finding | yes | Rule-triggered observations, never recommendations. | 1.0.0 | yes |

| `requires_rm_review` | boolean | yes | Whether RM review is required for the result. | 1.0.0 | yes |

### `facts`

Each fact has required `fact_id` (unique within the result), `metric` (non-empty string), `scope`,
`current_value` (any JSON-compatible value), `unit` (non-empty), and `as_of_date`. Optional fields
are `previous_value`, `change`, `currency`, `comparison_date`, `current_weight_pct`,
`previous_weight_pct`, `change_weight_pp`, `percentage_change`, `status`, and `evidence_ids`.
Exposure-change statuses are `added`, `exited`, `changed`, and `unchanged`; `evidence_ids` is the
optional list of supporting evidence IDs used by calculators that require fact-level traceability.
Monetary units such as `amount` and `currency_amount` require a non-empty currency. Percentage facts
must state their unit, for example `percentage_points`.

Facts are values, not prose conclusions. Version 1.0.0 has no recommendation field.

### `findings`

Each finding requires a unique `finding_id`, non-empty `finding_type`, `title`, and `description`,
severity (`info`, `low`, `medium`, or `high`), `fact_ids`, `evidence_ids`, and boolean
`requires_rm_review`. Evidence IDs must be non-empty and resolve to the result's evidence section;
fact IDs must resolve to facts. Findings must remain observations and may not instruct a buy, sell,
switch, rebalance, or other action. There is intentionally no `recommendation` field in v1.0.0.

### `evidence`

Evidence requires a unique `evidence_id`, non-empty `source_table`, non-empty `source_keys` object,
and JSON-compatible `value`. Optional fields are `field`, ISO `source_date`, and `description`.
Evidence may locate a database row or a field in the input snapshot; values must not be invented.

### `warnings`

Warnings require a unique `warning_id`, non-empty `warning_type` and `message`, and severity from
`info`, `low`, `medium`, or `high`. Optional `evidence_ids` must refer to evidence when supplied;
optional `source_reference` is a JSON object. A blocked result must contain at least one warning.

### `assumptions`

Assumptions require a unique `assumption_id`, non-empty `description` and `impact`, and boolean
`accepted`. They document limitations and must not conceal missing facts.

## Serialization and validation

Use `validate_result(payload)` to dispatch on `result_metadata.schema_version` and obtain a typed
`CalculatorResult`. Unsupported versions are rejected explicitly. Use `dumps_result()` and
`loads_result()` for strict JSON round-tripping. The validator rejects unknown fields, duplicate IDs,
invalid dates/enums, unresolved references, non-JSON values, blocked results without warnings, and
monetary facts without currency.

Complete example: `tests/contracts/fixtures/exposure_changes_result_v1.json`. It contains manually
defined example values only and is not an analytical result from the dataset.
