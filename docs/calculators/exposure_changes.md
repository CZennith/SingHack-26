# Exposure changes

`calculate_exposure_changes(current_exposure, previous_exposure)` compares two validated direct
exposure bases. It is pure Python and contains no DuckDB query. The two bases must have the same
client, direct/USD semantics, exposure-base version `1.0.0`, and different snapshot dates.

## Comparison rules

Groups are matched by `(scope_level, portfolio_id, dimension, key, instrument_id)` across each of
the seven exposure lists. The union of groups is compared, so a group appearing in only one base
is retained. Missing groups are represented as zero for comparison.

Each output fact has metric `exposure_change`, USD `current_value`, `previous_value`, and absolute
`change`, plus current/previous weights, percentage-point weight change, and one of:

- `added`: previous value is zero and current value is non-zero
- `exited`: current value is zero and previous value is non-zero
- `changed`: both values are non-zero and differ beyond the precision tolerance
- `unchanged`: values are equal within the precision tolerance, including both zero

When the previous value is zero, `percentage_change` is `null`; no infinite value is emitted. The
internal tolerance is `0.00000001` and is not a materiality rule. No fact is classified as material,
risky, concerning, or actionable, and no finding is generated by this initial calculator.

## Evidence and versions

Every fact includes two evidence IDs: one for the current exposure-base group and one for the
previous group. Evidence identifies client, date, dimension, group key, scope, and the
`market_value_usd` aggregation method. A missing group has an explicit zero comparison evidence
item rather than an omitted fact.

The result uses the existing calculator-result contract with `calculator_name: exposure_changes`
and `calculator_version: 1.0.0`. It separately records `input_current_exposure_version` and
`input_previous_exposure_version`, as well as the input snapshot schema/calculation versions.
Underlying references remain metadata and `look_through_included` remains false.

## Example

```python
from src.calculators.exposure_changes import calculate_exposure_changes

result = calculate_exposure_changes(current_exposure, previous_exposure)
```

The CLI reads validated current and previous snapshot JSON files. `--output-root` derives
`outputs/exposure_changes/{client_id}/{comparison_date}_to_{as_of_date}.json`; `--output` selects
an exact JSON path. Omit both to print JSON to stdout. Existing generated results require the
explicit `--overwrite` flag and are replaced atomically.

```bash
python3 -m src.calculators.exposure_changes \
  --current-snapshot /path/to/current_snapshot.json \
  --previous-snapshot /path/to/previous_snapshot.json \
  --output-root outputs
```

The result is validated through `validate_result()` before it is returned and is JSON-serializable.
The batch helper accepts either `{client_id: {date: snapshot}}`,
`{client_id: [snapshot, ...]}`, or `{(client_id, date): snapshot}` and compares the latest two
dates per client. Batch behavior is deterministic and fail-fast with the client ID in any error.

Known limitations: this calculator only describes direct exposure changes. It does not perform
look-through, event matching, liquidity or suitability analysis, note interpretation, performance
calculation, materiality classification, or recommendations.
